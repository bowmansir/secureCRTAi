# AI 会话隔离与 Markdown 表格

## 现象

- 关闭 Agent 后，普通上下文仍会读取 Agent 之前的执行结果。
- 一个标签正在生成或执行 Agent 时，其他标签无法输入，发送按钮也显示为暂停。
- AI 输出的 Markdown 表格被当作普通文本展示。

## 复现方式

1. 在服务器 A 开启 Agent 并发起任务。
2. 切换到服务器 B，观察输入框和发送按钮状态。
3. 关闭 Agent 后继续提问，观察回答是否引用 Agent 执行历史。
4. 让模型输出标准 Markdown 表格，观察表格是否正确渲染。

## 根因

- 普通对话与 Agent 对话共用同一个 `conversationKey`。
- `streaming`、`agentBusy`、停止标记和执行序号是 AI 面板全局状态。
- 轻量 Markdown 渲染器没有表格解析能力。

## 修复方式

- 对话历史按“终端标签 + 普通/Agent 模式”分别保存。
- 生成、执行、停止、草稿、环境信息和 Agent 开关按标签隔离。
- Agent 执行始终绑定发起时的 SSH 会话和服务器环境。
- 支持标准 Markdown 表格、列对齐、行内样式和横向滚动。
- 关闭标签时清理对应对话、草稿、执行通道和运行状态。

## 回归验证

- 用户已在 dev 中验证跨标签切换时可以继续输入和发送。
- `pnpm run build` 通过。
- `pnpm tauri build` 通过，并成功生成 MSI 与 NSIS 安装包。

## 同类隐患

- AI 流式增量目前会频繁触发消息列表重渲染。
- 对话历史尚未设置上下文预算或摘要策略。
- 前端停止生成目前不会取消后端 HTTP 请求。

以上性能项不影响本次功能正确性，后续应在长会话性能优化中集中处理。
