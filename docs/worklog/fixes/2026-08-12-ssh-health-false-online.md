## 现象

SSH 标签页明确显示连接失败，但会话侧栏仍为绿色，底栏健康检查显示全部在线。

## 复现方式

目标主机端口接受 TCP，但 SSH 握手、认证或会话连接失败时运行健康检查。现有实现只完成 TCP connect，仍返回在线；连接失败事件也不会使此前的在线健康结果失效。

## 根因

健康检查把“TCP 端口可达”误当成“SSH 在线”，没有复用真实终端的 SSH 握手、主机密钥校验与认证。同时，标签页 `connected/closed` 状态只更新标签，不同步权威程度更高的健康状态。

## 修复方式

1. 后端健康检查不再只探测 TCP 端口，改为复用真实终端连接链路，完成 SSH 握手、主机密钥校验和所选认证方式；只有认证成功才返回在线。
2. 每次探测仍受单机超时和全局并发限制约束；认证成功后主动断开探测连接。
3. 实际 SSH 标签页连接成功时立即写入在线状态；初次连接失败或重连耗尽时立即写入离线状态，避免旧的绿色结果残留。
4. 用户主动关闭标签不等价于主机离线，因此无失败消息的 `closed` 不覆盖最近检查结果；同一会话仍有已连接标签时，另一个标签失败也不会错误覆盖在线状态。
5. 健康检查超时由 2.5 秒调整为 6 秒，为握手和认证留出预算。

## 同类隐患

SFTP 与 SSH 共用标签状态入口，但健康状态同步会核对标签类型，仅 SSH 标签影响 SSH 健康结果。分屏 SSH 窗格使用同一入口，并额外检查同一会话是否仍有其他已连接窗格。

健康检查现在会执行真实认证，因此会比端口探测更慢，也可能触发远端认证审计日志；这是将“在线”定义为“当前保存配置可真实登录”所必需的边界。本次没有连接生产主机做实机探测，避免在未发布版本外主动使用保存的远端凭据。
