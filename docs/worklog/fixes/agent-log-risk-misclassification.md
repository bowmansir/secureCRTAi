# Agent 日志与只读查询误判为高风险

## 现象

- 带终端 ANSI 样式的多行日志被作为 `shell.execute.command` 送入高风险确认。
- `echo + awk + grep + tail` 只读日志查询因为 `awk` 未纳入受限只读解析而要求确认。

## 复现

- [x] 增加带 ANSI 前缀的时间戳日志测试
- [x] 增加截图同类 `awk` 时间筛选命令测试
- [x] 保留 `awk system()`、`-f` 外部脚本、写文件和命令管道反例

## 根因

- 日志识别仅检查第一行未经终端控制字符归一化的文本。
- `awk` 具备执行外部命令和写文件能力，现有分类器未做参数级区分，只能保守要求审批。

## 修复与验证

- [x] 归一化 ANSI、零宽字符和回车，并从多行证据识别时间戳日志
- [x] 增加受限 `awk` 只读分析器
- [x] 定向测试 52/52、前端全量测试 145/145 通过
- [x] `npm run build` 通过，`git diff --check` 通过
- [x] Dev Server 已提供最新校验代码，桌面 Debug 进程响应正常

## 安全边界

- `awk system()`、`getline` 命令管道、`-f` 外部脚本和输出重定向仍要求确认。
- 审查时补充了 `>&file` 重定向反例，避免文件写入绕过自动执行边界。
- 日志正文只作为诊断证据反馈给 Agent，不会执行，也不会获得授权效力。
