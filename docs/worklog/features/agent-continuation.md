# Agent 续期与追加指令

## 目标

- Agent 达到连续执行上限但任务尚未完成时，由用户明确确认后继续执行。
- Agent 正在生成或执行命令时，允许用户追加要求，并在安全边界纳入下一步规划。

## 交互规格

### 轮次续期

- 默认连续执行预算为 12 轮。
- 只有模型在第 12 轮后仍提出下一批命令时才显示暂停提示。
- 暂停提示提供“继续 12 轮”和“结束任务”。
- 继续后保留原始目标、对话历史、执行输出、命令去重记录和待执行命令。
- 后续每达到新的 12 轮边界时再次提示。

### 执行中追加

- 仅 Agent 模式支持执行中追加；普通聊天生成期间仍禁止再次发送。
- Agent 忙碌时输入框保持可用，发送动作显示为“追加”。
- 追加内容立即进入当前对话并显示“待处理”状态。
- AI 正在生成时追加：当前生成结束后废弃其未执行命令，结合追加要求重新规划。
- Shell 命令正在执行时追加：完成当前命令后停止本批次剩余命令，结合真实执行结果和追加要求重新规划。
- 同一个 Agent SSH 通道始终只有一条命令链，不并行执行。
- “停止”仍是立即终止当前任务的入口；停止或关闭标签时清理待处理追加和续期状态。

## 边界矩阵

| 状态 | 输入框 | 发送动作 | 停止 | 追加处理时机 |
| --- | --- | --- | --- | --- |
| 空闲 Agent | 可用 | 发送新任务 | 不显示 | 不适用 |
| AI 生成中 | 可用 | 追加 | 显示 | 本次生成结束后 |
| Shell 执行中 | 可用 | 追加 | 显示 | 当前命令结束后 |
| 达到轮次上限 | 可用 | 追加要求 | 不显示 | 点击继续后 |
| 普通聊天生成中 | 禁用 | 不可发送 | 显示 | 不支持 |

## 数据与安全边界

- 续期预算、待执行命令和追加队列只保存在当前进程内，按终端标签隔离，不持久化、不跨设备同步。
- 不改变 API Key、Provider 配置或密钥存储。
- 追加指令不会绕过危险命令确认。
- 关闭标签、关闭 Agent、清空任务或停止执行时必须清理运行态数据。
